# Problem 2: Daily Sales

Leadership wants to see how much we sell each day. You'll build one small table in three parts.

## Part 1: Count orders per day ⬜

Create `models/marts/daily_sales.sql` with one row per day:

| column | meaning |
|---|---|
| order_date | the day |
| total_orders | every order that day, any status |
| completed_orders | only completed orders |
| revenue | sum of `amount` for completed orders only |

**Hints:**

- Use `ref('fct_orders')`. It already has `order_date`, `status` and `amount`.
- This is just a `group by order_date`. No joins needed.
- To count or sum only completed orders, put a `case when` inside: `sum(case when status = 'completed' then amount else 0 end)`. You did this in `int_customer_metrics`.
- Oct 2 only has a cancelled order, so its revenue should be **0**.
- Preview with Ctrl+Enter. You should get **16 rows**.

## Part 2: Add a running total ⬜

Add one more column:

| column | meaning |
|---|---|
| running_revenue | revenue from Oct 1 up to and including this day |

**Hints:**

- This is a window function, like `customer_order_number` in `fct_orders`: `sum(revenue) over (order by order_date)`.
- No `partition by` this time, because we want **one** running total for the whole table, not one per customer.
- You can't put a window function on top of a `group by` result in the same select easily. Do the `group by` in a CTE first, then add the window function in a second CTE.

## Part 3: Tests ⬜

In `models/marts/schema.yml`, add `daily_sales` with:

1. `order_date`: `unique` and `not_null`
2. `revenue`: `not_null`

Then run `dbt build --select daily_sales` and get everything green.

## Bonus (only if you want more)

- Add `cancelled_orders`.
- Add `revenue_change`, today's revenue minus yesterday's, using `lag(revenue) over (order by order_date)`.
- Notice there are no rows after Oct 16. If you wanted every day up to Oct 21 with zeros, you'd need a **date spine** (that could be Problem 3).
