# Problem 3: Every Day, Even With No Sales

`daily_sales` only has rows for days that had orders, so it stops on **Oct 16**. Leadership wants a chart of the first three weeks (**Oct 1 to Oct 21**), and days with no sales should show **0** instead of being missing. You'll build it in three parts.

## Part 1: Build a calendar ⬜

You can't make a row for a day that has no orders by grouping orders, because the day isn't there. So first you build a table that is **just dates**, one row per day. This is called a **date spine**.

Create `models/intermediate/int_dates.sql` with one row per day from **Oct 1 to Oct 21, 2026**:

| column | meaning |
|---|---|
| sales_date | the day |

**Hints:**

- dbt_utils is already installed, and it has a macro that writes the SQL for you:

  ```sql
  {{ dbt_utils.date_spine(
      datepart="day",
      start_date="cast('2026-10-01' as date)",
      end_date="cast('2026-10-22' as date)"
  ) }}
  ```

- Why **Oct 22**? The end date is **not included**, so you go one day past the last day you want.
- The macro names its column `date_day`. Put the macro in a CTE, then select from it.
- `date_day` comes out as a **timestamp** (`2026-10-01 00:00:00`), not a date. Use `cast(date_day as date) as sales_date` so it matches `order_date` in `daily_sales`.
- Preview it. You should get **21 rows**.
- Your `models/playground/date_spine.sql` won't compile yet. Its `end_date` has a stray `)` inside the quotes.

## Part 2: Join sales onto the calendar ⬜

Create `models/marts/daily_sales_all_days.sql` with these columns:

| column | meaning |
|---|---|
| sales_date | from `int_dates` |
| total_orders | from `daily_sales`, **0** on days with no orders |
| completed_orders | from `daily_sales`, **0** on days with no orders |
| revenue | from `daily_sales`, **0** on days with no orders |
| running_revenue | revenue from Oct 1 up to and including this day |

**Hints:**

- Start `from` the calendar (`int_dates`) and **left join** `ref('daily_sales')` on `int_dates.sales_date = daily_sales.order_date`. This is the same idea as customer 108 in Problem 1. Starting from the table that has **every** row keeps the rows with nothing to join to.
- After the left join, Oct 17 to Oct 21 have `null` in every sales column. Turn them into 0 with `coalesce(revenue, 0)`.
- **Don't reuse `daily_sales.running_revenue`.** It's null on the empty days too. Calculate it again with `sum(...) over (order by sales_date)` **after** the `coalesce`. Do the join and coalesce in one CTE, then add the running total in the next.

## Part 3: Tests ⬜

In `models/marts/schema.yml`, add `daily_sales_all_days` with:

1. `sales_date`: `unique` and `not_null`
2. `revenue`: `not_null`. This test proves your `coalesce` worked.

Then run `dbt build --select +daily_sales_all_days` and get everything green. (The `+` means "build everything this model depends on first".)
